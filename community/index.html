Community

Apache Asyncband (Incubating) is an effort undergoing incubation at the Apache Software Foundation, sponsored by the Apache Incubator PMC. Project governance, release votes, and design decisions happen in the open following the Apache Way.

Mailing lists​

Mailing lists are the primary record for project decisions and release votes:

ListPurposeSubscribeArchives
dev@asyncband.apache.orgDesign discussions, proposals, and release votesSubscribeArchives
commits@asyncband.apache.orgAutomated notifications for commits, issues, PRsSubscribeArchives

To unsubscribe from either list, send an email to dev-unsubscribe@asyncband.apache.org or commits-unsubscribe@asyncband.apache.org.

GitHub​

  • GitHub Issues: Bug reports and concrete feature requests.
  • GitHub Discussions: Usage questions, concurrency trade-off discussions, and early design ideas.
  • apache/asyncband: Core Rust crate, runnable examples, and benchmarks.
  • apache/asyncband-site: Source repository for this website and engineering blog.

Contributing​

Contributions of all kinds are welcome, including bug reports, benchmark cases, documentation improvements, code reviews, and primitive implementations. When proposing a new concurrency primitive, evaluate it against Asyncband's core boundary: reusable coordination mechanisms belong in the library, while task spawning, timers, retries, and runtime scheduling policy remain with the caller.

  • Browse good first issue and help wanted tasks on GitHub to find self-contained starting points.
  • Follow the repository workflow, Rust style, and documentation conventions in AGENTS.md when preparing a pull request.
  • Release managers follow the documented, repeatable release procedure and license audit checklist to build and verify Apache source releases.

Governance and decision-making​

  • Project roster: The public list of active PPMC members, committers, and mentors is maintained on the Apache Phonebook.
  • Written asynchronous discussion: Substantive architecture, API contract, roadmap, release, and governance discussions happen in writing on dev@asyncband.apache.org or in public GitHub issues and pull requests. Any off-list or synchronous discussion that affects the project is summarized back to dev@asyncband.apache.org before a decision is finalized.
  • Consensus and voting: Routine code and documentation changes proceed through pull request review and lazy consensus. Software releases, committer and PPMC elections, and formal policy decisions follow standard Apache voting rules (+1 / 0 / -1, open for at least 72 hours). Release votes require at least three binding +1 votes and more +1 than -1 votes on dev@asyncband.apache.org, followed during incubation by approval from the Apache Incubator PMC on general@incubator.apache.org.
  • Vetoes: Per Apache voting rules, vetoes (-1) apply only to code modifications and must be accompanied by a clear technical explanation.
  • Maturity assessment: See the Community Report & Maturity Assessment for a point-in-time evaluation against the Apache Project Maturity Model.

Roles and meritocracy​

Apache Asyncband operates as a meritocracy in which contributors participate as individuals rather than representatives of an employer or organization:

  • Contributors: Anyone who reports bugs, joins design discussions, reviews pull requests, writes documentation, or submits code.
  • Committers: Contributors who demonstrate sustained, constructive engagement and good engineering judgment may be nominated by any PPMC member and elected by private PPMC vote following the ASF Incubator PPMC guide. Committers sign the Apache Individual Contributor License Agreement (ICLA), hold write access to project repositories, and help review contributions.
  • PPMC members: Committers who take ongoing responsibility for project stewardship, release verification and voting, contributor mentorship, security response, and Incubator board reporting may be elected to the Podling Project Management Committee (PPMC).

Security​

Do not report suspected security vulnerabilities in public GitHub issues or mailing lists. Report them privately to security@apache.org with Asyncband in the subject line, following the ASF vulnerability reporting process. See SECURITY-THREAT-MODEL.md in the main repository for scope details.

Apache Asyncband (Incubating) is an effort undergoing incubation at the Apache Software Foundation (ASF), sponsored by the Apache Incubator PMC. Incubation is required of all newly accepted projects until a further review indicates that the infrastructure, communications, and decision making process have stabilized in a manner consistent with other successful ASF projects. While incubation status is not necessarily a reflection of the completeness or stability of the code, it does indicate that the project has yet to be fully endorsed by the ASF.

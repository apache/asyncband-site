Community Report & Maturity Assessment

Updated at: 2026-11-22. This page is a point-in-time community report and self-assessment prepared during the graduation readiness review of Apache Asyncband (Incubating) (apache/asyncband#422) rather than a continuously updated dashboard. After graduation, individual counts and links may become historical; refer to the Community and Downloads pages and the GitHub repositories for current project state.

Incubation community summary​

Apache Asyncband (Incubating) entered the Apache Incubator on 2026-08-18 following the proposal discussion and acceptance vote. VP, Brand Management approved the "Apache Asyncband" name in PODLINGNAMESEARCH-257, and initial contributions are covered through contributor ICLAs along the CLA-based path in the Podling IP Clearance guide, recorded on the Incubator status page.

During incubation, the community has published four ASF-approved source releases, each driven by a different release manager:

VersionDateRelease ManagerLinks
0.7.22026-09-10Zili Chen (tison)Tracking issue · PPMC result · IPMC result
0.7.32026-09-29Haixu Ouyang (orthur)Tracking issue · PPMC result · IPMC result
0.7.42026-10-25Bohao Zhang (iqwqi)Tracking issue · PPMC result · IPMC result
0.8.02026-11-16Yijun Zhao (ariesdevil)Tracking issue · PPMC result · IPMC result

Over the same period, the PPMC elected three new committers and PPMC members: Bohao Zhang (iqwqi), Yijun Zhao (ariesdevil), and Jinlin Zhu (nanami). The ten-member PPMC and committer roster spans multiple legally independent employers, open-source communities, and individual contributors, with no single organization holding control.

Day-to-day maintenance is shared across committers and contributors, covering release management, concurrency primitive and channel development, code reviews, benchmarking, and website and blog maintenance, with design discussions and roadmaps coordinated in public on GitHub and the project mailing list.

Apache Project Maturity Model assessment​

The tables below evaluate Apache Asyncband (Incubating) against the Apache Project Maturity Model. Feedback and updates from PPMC members, mentors, and the wider community are welcome on the development mailing list.

Code​

IDDescriptionStatus
CD10The project produces Open Source software for distribution to the public, at no charge.YES. Source code in apache/asyncband and apache/asyncband-site is distributed publicly at no charge under the Apache License 2.0.
CD20Anyone can easily discover and access the project's code.YES. Both repositories are linked directly from the navigation bar, footer, Downloads, and Community pages.
CD30Anyone using standard, widely-available tools, can build the code in a reproducible way.YES. The Rust crate builds and tests reproducibly with stable Cargo (MSRV 1.86.0) as documented in the repository README, and the website builds with pnpm and Node.js.
CD40The full history of the project's code is available via a source code control system, in a way that allows anyone to recreate any released version.YES. Full Git commit history and release tags (0.7.2 through 0.8.0) are publicly available in ASF-hosted Git repositories.
CD50The source code control system establishes the provenance of each line of code in a reliable way, based on strong authentication of the committer. When third parties contribute code, commit messages provide reliable information about the code provenance.YES. Repositories are managed by ASF Infrastructure via GitBox and GitHub with authenticated committer write access, branch protection, and pull-request review attribution.

Licenses and copyright​

IDDescriptionStatus
LC10The Apache License, version 2.0, covers the released code.YES. Released archives and repositories carry LICENSE and NOTICE, with ASF license headers enforced automatically in CI.
LC20Libraries that are mandatory dependencies of the project's code do not create more restrictions than the Apache License does.YES. Asyncband enables zero features by default and depends only on the Rust standard library unless optional primitives are selected; optional dependencies use permissive Apache-2.0 or MIT licenses, audited during every release.
LC30The libraries mentioned in LC20 are available as Open Source software.YES. All optional crate and build dependencies are OSI-approved open-source packages published on crates.io or npm.
LC40Committers are bound by an Individual Contributor Agreement (the "Apache iCLA") that defines which code they may commit and how they need to identify code that is not their own.YES. All ten committers have signed Apache ICLAs on file, verified against ASF ICLA and LDAP records on the Incubator status page.
LC50The project clearly defines and documents the copyright ownership of everything that the project produces.YES. Source files carry standard ASF headers, incorporated third-party notices are preserved and audited per release, and initial CLA-based provenance is recorded on the Incubator status page.

Releases​

IDDescriptionStatus
RE10Releases consist of source code, distributed using standard and open archive formats that are expected to stay readable in the long term.YES. Official source releases are distributed as .tar.gz archives through the ASF distribution and archive mirrors, linked from Downloads.
RE20The project's PMC (Project Management Committee, see CS10) approves each software release in order to make the release an act of the Foundation.YES. All four ASF releases (0.7.2, 0.7.3, 0.7.4, and 0.8.0) passed two-stage votes with at least three binding +1 votes on the project development list and the Incubator general list.
RE30Releases are signed and/or distributed along with digests that anyone can reliably use to validate the downloaded archives.YES. Every release archive ships with a detached PGP signature, a SHA-512 checksum, and the project KEYS file, with verification steps documented on Downloads.
RE40The project can distribute convenience binaries alongside source code, but they are not Apache Releases, they are provided with no guarantee.YES. Convenience Rust packages on crates.io are built from the voted source release and explicitly documented on Downloads as supplemental to the official ASF source release.
RE50The project documents a repeatable release process so that someone new to the project can independently generate the complete set of artifacts required for a release.YES. The end-to-end release procedure is checked into the repository and has been executed independently by four different release managers.

Quality​

IDDescriptionStatus
QU10The project is open and honest about the quality of its code. Various levels of quality and maturity for various modules are natural and acceptable as long as they are clearly communicated.YES. Missing public documentation is denied at compile time, API docs state cancellation, panic, deadlock, and synchronous-interop contracts explicitly, and open design or performance trade-offs are tracked in public GitHub issues.
QU20The project puts a very high priority on producing secure software.YES. Unsafe concurrency code is minimized, covered by integration and sanitizer checks, and scoped in a dedicated security threat model.
QU30The project provides a well-documented, secure and private channel to report security issues, along with a documented way of responding to them.YES. Private vulnerability reporting via security@apache.org and response responsibilities are documented on Community and in the repository threat model.
QU40The project puts a high priority on backwards compatibility and aims to document any incompatible changes and provide tools and documentation to help users transition to new features.YES. Breaking changes, new features, and upgrade notes are documented per release in CHANGELOG.md, and MSRV 1.86.0 follows an explicit minor-bump policy.
QU50The project strives to respond to documented bug reports in a timely manner.YES. Bug reports and pull requests in GitHub Issues receive prompt triage, review, and regression test coverage from committers.

Community​

IDDescriptionStatus
CO10The project has a well-known homepage that points to all the information required to operate according to this maturity model.YES. The official website provides direct access to API documentation, verified downloads, mailing lists, repositories, governance guidance, security reporting, and ASF foundation policies, with zero third-party runtime assets.
CO20The community welcomes contributions from anyone who acts in good faith and in a respectful manner, and who adds value to the project.YES. Contributions are open without issue reservation, governed by the ASF Code of Conduct, with workflow and contribution guidance on Community.
CO30Contributions include source code, documentation, constructive bug reports, constructive discussions, marketing and generally anything that adds value to the project.YES. Code, benchmark suites, documentation, blog posts, website design, release verification, and design reviews are all recognized across committer elections and reviews.
CO40The community strives to be meritocratic and gives more rights and responsibilities to contributors who, over time, add value to the project.YES. Three new committers and PPMC members (iqwqi, ariesdevil, and nanami) have been nominated and elected during incubation based on sustained project contributions.
CO50The project documents how contributors can earn more rights such as commit access or decision power, and applies these principles consistently.YES. Meritocratic criteria and the PPMC nomination and election path are practiced consistently and documented publicly under Roles and meritocracy.
CO60The community operates based on consensus of its members (see CS10) who have decision power. Dictators, benevolent or not, are not welcome in Apache projects.YES. Releases, membership additions, naming, and graduation readiness are decided collectively on project mailing lists rather than by any single individual.
CO70The project strives to answer user questions in a timely manner.YES. Questions and design inquiries are answered promptly across the development mailing list, GitHub Discussions, and GitHub Issues.

Consensus building​

IDDescriptionStatus
CS10The project maintains a public list of its contributors who have decision power. The project's PMC (Project Management Committee) consists of those contributors.YES. The public PPMC and committer roster is linked from Governance and decision-making and maintained on the Apache Phonebook.
CS20Decisions require a consensus among PMC members and are documented on the project's main communications channel. The PMC takes community opinions into account, but the PMC has the final word.YES. Formal project decisions are discussed and voted on the development mailing list (with private personnel votes on the private list per ASF policy) and archived publicly on Apache Pony Mail.
CS30The project uses documented voting rules to build consensus when discussion is not sufficient.YES. Lazy consensus and formal Apache voting rules are documented under Governance and decision-making.
CS40In Apache projects, vetoes are only valid for code commits. The person exercising the veto must justify it with a technical explanation, as per the Apache voting rules defined in CS30.YES. No code vetoes have been exercised to date, and the technical-justification requirement is explicitly documented under Governance and decision-making.
CS50All "important" discussions happen asynchronously in written form on the project's main communications channel. Offline, face-to-face or private discussions that affect the project are also documented on that channel.YES. Naming, release votes, API contracts, roadmap planning, and graduation readiness are all conducted and recorded asynchronously in public written channels.

Independence​

IDDescriptionStatus
IN10The project is independent from any corporate or organizational influence.YES. The ten PPMC members and committers are affiliated with multiple independent companies, open-source foundations, and academic or individual backgrounds; no single employer or commercial entity directs project roadmap or votes.
IN20Contributors act as themselves, not as representatives of a corporation or organization.YES. Contributors and PPMC members participate in their individual capacities on public ASF channels, bound by individual ICLAs and the Apache Way.

Incubation is required of all newly accepted projects until a further review indicates that the infrastructure, communications, and decision making process have stabilized in a manner consistent with other successful ASF projects.
